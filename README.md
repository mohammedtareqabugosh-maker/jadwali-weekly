# جدولي الأسبوعي

تطبيق ويب تقدّمي (PWA) عربي باتجاه RTL لإدارة أسبوعك، مبني بـ React وTypeScript وVite. يعمل محليًا بالكامل بعد تحميل موارده، ولا يحتاج إلى حساب أو خادم أو مفتاح API.

## الوظائف

- جدول من سبعة أيام مع خط زمني مستقل لكل يوم.
- إضافة سريعة أو مفصلة، وتعديل المهام ونسخها وحذفها والتراجع عن الحذف ونقلها وتكرارها.
- إنجاز المهام وإلغاء الإنجاز، مع ربط الحالة بالتاريخ والمهمة حتى لا تنتقل حالة أسبوع إلى آخر.
- البحث والتصفية، وعرض المهمة الحالية والتالية ونسبة التقدم والمهام المتبقية.
- التحقق من الوقت والمدة، ودعم المهمة التي تنتهي عند `00:00`، وتحذير التعارض الذي لا يُحفظ إلا بعد تأكيد صريح.
- أهداف وعادات قابلة للإضافة والتعديل والحذف وتحديث التقدم، مع ربط اختياري بالمهام.
- ملاحظات قابلة للبحث والتحرير، مع طوابع الوقت وربط اختياري بيوم أو مهمة.
- تقارير يومية وأسبوعية، وساعات حسب النوع، ووقت مشغول مدموج حتى لا تُحتسب الفترات المتداخلة مرتين، وسلسلة التزام مشتقة من الإنجاز الفعلي.
- وجبات كعناصر حقيقية في الجدول، دون محتوى غذائي مفروض داخل التطبيق.
- استيراد وتصدير JSON للتكامل اليدوي مع «مساعدي الغذائي»، مع تحديث الوجبة نفسها بدل تكرارها عند تطابق المعرّف.
- «مخرج الطوارئ»: محادثة محلية قائمة على قواعد وفروع واضحة، تراجع وتعيد البدء، وتعرض خطة بديلة قبل تطبيقها. لا يستخدم نموذجًا لغويًا أو API مدفوعًا.
- نسخة احتياطية كاملة بصيغة JSON، ومعاينة محتويات النسخة قبل الاستعادة، ورفض الملف غير الصالح دون استبدال البيانات الحالية.
- مظهر فاتح وداكن، تخطيط هاتفي أولًا، أهداف لمس مناسبة، دعم مناطق الأمان، وملفات Manifest وService Worker وأيقونات محلية وخط Tajawal محلي.

## الخصوصية والتخزين

- تُحفظ بيانات التطبيق في IndexedDB داخل المتصفح باسم قاعدة `jadwali-weekly`.
- يستخدم localStorage لبيانات وصفية محدودة مثل المظهر، وليس بديلًا عن قاعدة البيانات.
- لا يرسل التطبيق بياناتك تلقائيًا إلى أي خادم خارجي، ولا يحتوي على مفاتيح API أو كلمات مرور.
- لا توجد مزامنة سحابية أو مزامنة بين الأجهزة. البيانات مرتبطة بالمتصفح والأصل (origin) الذي فتحت منه التطبيق.
- تغيير النطاق أو المنفذ، أو استخدام متصفح آخر، أو حذف بيانات الموقع قد يمنع الوصول إلى النسخة المحلية. صدّر نسخة احتياطية دوريًا.
- التكامل مع «مساعدي الغذائي» يتم بملفات JSON يختارها المستخدم. التطبيقان المستقلان على أصلين مختلفين لا يتشاركان localStorage أو IndexedDB.
- تحديث واجهة التطبيق لا يحذف قاعدة البيانات؛ أما حذف بيانات الموقع من المتصفح فهو إجراء منفصل قد يمحوها.

## التشغيل محليًا

المتطلبات: إصدار حديث من Node.js يدعم Vite 7 (يوصى بـ Node.js 22)، وnpm.

```bash
npm install
npm run dev
```

يفتح خادم التطوير على `http://localhost:3000`.

أوامر المشروع:

```bash
npm run lint       # فحص الشيفرة
npm test           # اختبارات الوحدة
npm run build      # بناء نسخة الإنتاج داخل dist
npm run preview    # معاينة نسخة الإنتاج محليًا
```

> التسجيل الفعلي لـ Service Worker يحدث في بناء الإنتاج فقط. لاختبار العمل دون اتصال استخدم `npm run build` ثم `npm run preview`، وليس خادم التطوير.

## التثبيت والعمل دون اتصال

يلزم HTTPS عند الاستضافة العامة، ويُسمح بـ HTTP على localhost أثناء التطوير. افتح نسخة الإنتاج مرة مع اتصال بالإنترنت وانتظر اكتمال تحميلها.

- **iPhone:** افتح الموقع في Safari، ثم «مشاركة» ← «إضافة إلى الشاشة الرئيسية».
- **Android / Chrome:** استخدم خيار «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية» عند توفره.
- **سطح المكتب:** استخدم أيقونة التثبيت في شريط العنوان إن ظهرت، أو زر التثبيت داخل الإعدادات عندما يتيحه المتصفح.

بعد تجهيز ذاكرة التخزين المؤقت، يمكن فتح واجهة التطبيق واستخدام وظائفه المحلية دون اتصال. أول زيارة قبل اكتمال تحميل الموارد ليست اختبارًا صالحًا للعمل دون اتصال. قد تختلف بعض سلوكيات PWA بحسب إصدار النظام والمتصفح.

## النشر على GitHub Pages

المشروع يستخدم `base: './'` في `vite.config.ts`، لذا يصلح لمسارات GitHub Pages الفرعية. يوجد سير عمل جاهز في `.github/workflows/deploy.yml`.

1. أنشئ مستودعًا فارغًا في حسابك على GitHub.
2. من مجلد المشروع نفّذ، بعد استبدال اسم المستخدم والمستودع:

```bash
git init
git add .
git commit -m "Initial weekly schedule app"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

3. في صفحة المستودع افتح **Settings → Pages**، واختر **GitHub Actions** كمصدر للنشر.
4. ادفع أي تغيير لاحق إلى فرع `main`، أو شغّل سير العمل يدويًا من تبويب **Actions** إن كان متاحًا.
5. بعد نجاح سير العمل سيعرض GitHub رابط الموقع. افتحه مرة عبر الإنترنت قبل اختبار التثبيت أو العمل دون اتصال.

هذه تعليمات فقط؛ إنشاء المستودع والدفع والنشر تتطلب حسابك وصلاحياتك ولم تُنفّذ ضمن ملفات المشروع.

يمكن أيضًا نشر محتويات `dist/` على أي استضافة ملفات ثابتة تدعم HTTPS. لا حاجة إلى خادم تطبيق أو قاعدة بيانات خارجية.

## مخطط وجبة JSON

الحد الأدنى المطلوب هو معرّف ثابت واسم ويوم ووقت بداية. أرقام الأيام تتبع JavaScript: الأحد `0`، الاثنين `1`، …، السبت `6`.

```json
{
  "id": "meal-stable-001",
  "name": "اسم الوجبة",
  "kind": "عشاء",
  "day": 5,
  "start": "20:30",
  "end": "21:00",
  "calories": 420,
  "protein": 25,
  "carbs": 45,
  "fat": 14,
  "source": "مساعدي الغذائي"
}
```

يمكن استخدام `externalId` بدل `id`، و`title` بدل `name`، و`time` بدل `start`. إذا حُذف `end` تكون المدة الافتراضية 60 دقيقة. الحقول الغذائية اختيارية ويمكن وضعها داخل كائن `nutrition`. يقبل المستورد أيضًا غلافًا على الشكل:

```json
{
  "schema": "jadwali-meal-v1",
  "meal": {
    "externalId": "meal-stable-001",
    "name": "اسم الوجبة",
    "day": 5,
    "start": "20:30",
    "end": "21:00"
  }
}
```

عند استيراد المعرّف نفسه لاحقًا تُحدَّث الوجبة القائمة مع الحفاظ على معرّف المهمة الداخلي وعلاقة الإنجاز بها. لا يؤدي الاستيراد إلى اتصال شبكي أو ربط مباشر بين تخزين التطبيقين.

## النسخ الاحتياطي والاستعادة

من **المزيد ← الإعدادات**:

1. اختر «تصدير كل البيانات» لتنزيل JSON يتضمن المهام والأهداف والملاحظات والإنجازات والإعدادات.
2. عند الاستعادة اختر الملف وانتظر التحقق من بنيته وصحة الأوقات والحقول.
3. راجع الملخص، ثم أكّد الاستبدال أو ألغِ العملية.

الملف غير الصالح أو أكبر من 10 ميغابايت يُرفض قبل تعديل البيانات الحالية. الاستعادة المؤكدة تستبدل بيانات المتصفح الحالية؛ صدّر نسخة حالية أولًا عند الحاجة.

## بنية الشيفرة

| المسار | الغرض |
|---|---|
| `src/App.tsx` | حالة التطبيق والتنقل والحفظ والنوافذ والرسائل |
| `src/types.ts` | أنواع البيانات والثوابت العربية |
| `src/data/seed.ts` | الجدول الابتدائي القابل للتعديل |
| `src/lib/time.ts` | الأوقات والتعارض والفترات المتاحة والإنجاز |
| `src/lib/stats.ts` | الإحصائيات والوقت المشغول والسلسلة |
| `src/lib/storage.ts` | IndexedDB والنسخ الاحتياطي |
| `src/lib/validation.ts` | التحقق من البيانات والاستيراد |
| `src/lib/meals.ts` | استيراد الوجبات وتحديثها وتصديرها |
| `src/lib/emergency.ts` | فروع المحادثة وبناء الخطة وتطبيقها |
| `src/components/` | محرر المهام والخط الزمني والنوافذ والعناصر المشتركة |
| `src/pages/` | صفحات الجدول والأهداف والملاحظات والوجبات والتقارير والإعدادات |
| `src/index.css` | نظام التصميم والتجاوب والمظهر الداكن والطباعة |
| `public/manifest.webmanifest` | بيانات تثبيت PWA |
| `public/sw.js` | تخزين موارد التطبيق والعمل دون اتصال |
| `public/icons/` | أيقونات التثبيت وApple |
| `src/lib/*.test.ts` | اختبارات الوحدة |

لتغيير الجدول الابتدائي عدّل `src/data/seed.ts`. لا يؤثر ذلك في بيانات مستخدم سبق أن أنشأ قاعدته المحلية؛ ولا يُعاد زرع البيانات فوق بياناته عند التحديث.

## حدود معروفة

- لا توجد مزامنة سحابية أو إشعارات أو مشاركة مباشرة بين الأجهزة.
- التثبيت والعمل دون اتصال يخضعان لدعم المتصفح ونظام التشغيل وسياسات التخزين لديه.
- «مخرج الطوارئ» مساعد قواعد محلي، وليس تشخيصًا طبيًا أو خدمة طوارئ. في الخطر الحقيقي يعرض توجيهًا لطلب مساعدة بشرية عاجلة ولا يدّعي الاتصال بأي جهة.
- راجع `TESTING.md` لمعرفة الاختبارات المنفذة فعلًا وما لم يُختبر، بما في ذلك التثبيت على iPhone حقيقي.
